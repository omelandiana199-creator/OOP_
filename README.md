# Лабораторна робота №1
**Тема:** Класи. Основні їх елементи. Інтерфейси. Суть та особливості

**Мета роботи:** Отримати практичні навички для розробки програм з використання класів та інтерфейсів у мові Java.

**Завдання:**
Згідно з варіантом №4, необхідно розробити модель прийому замовлень у харчувальні. Розроблена модель повинна містити не менше шести класів із глибиною ієрархії мінімум три рівні. Кожен клас має бути розміщений в окремому файлі. До основної моделі вимагається додати та імплементувати два інтерфейси. У рамках математичної складової роботи, також реалізувати 10 запропонованих математичних задач.

**Опис виконання роботи:**
Відповідно до поставленого завдання, було спроєктовано та програмно реалізовано об'єктно-орієнтовану модель прийому замовлень у харчувальні. Архітектуру моделі побудовано на базі ієрархії з шести класів, глибина успадкування якої становить три рівні. З метою дотримання стандартів організації коду, кожен створений клас було винесено в окремий файл. Додатково архітектуру було розширено: створено та імплементовано два інтерфейси, що доповнюють функціонал основних об'єктів.

Окремим розширеним етапом стала алгоритмічна реалізація повного комплексу з 10 математичних задач. Для їх вирішення було розроблено єдиний утилітний клас із активним застосуванням сучасних інструментів Java Stream API. Серед успішно реалізованих завдань: знаходження суми масиву, обчислення середнього арифметичного, пошук мінімуму та максимуму, перевірка та фільтрація простих чисел, обчислення факторіалу (ітеративно та рекурсивно), реверс масиву, генерація чисел Фібоначчі, видалення дублікатів, сортування бульбашкою з підрахунком обмінів, а також підрахунок парних і непарних чисел. Правильність роботи як бізнес-логіки моделі харчувальні, так і всіх математичних методів була підтверджена за допомогою модульного тестування (фреймворк JUnit 5).

**Висновок:**
У результаті виконання лабораторної роботи було успішно застосовано та закріплено практичні навички розробки програм із використанням класів та інтерфейсів у мові Java. Завдяки проєктуванню моделі прийому замовлень у харчувальні було детально досліджено механізми успадкування та особливості побудови багаторівневих ієрархій класів. Винесення кожного класу в окремий файл на практиці довело необхідність чіткої структуризації програмного коду, а процес імплементації інтерфейсів наочно продемонстрував гнучкі підходи до розширення функціональності об'єктів.

Водночас було значно поглиблено навички розробки алгоритмів шляхом програмної реалізації 10 математичних задач. Застосування функціонального підходу (Stream API) дозволило суттєво оптимізувати код, а написання модульних тестів закріпило розуміння важливості автоматизованої перевірки для забезпечення якості програмного забезпечення. Отримані знання є міцною базою для подальшого проєктування надійних об'єктно-орієнтованих систем.


# Лабораторна робота №3

**Тема:** Відпрацювання навичок роботи з класами, об'єктами та базовими механізмами ООП

**Мета:** Відпрацювати навички володіння класами, об'єктами та іншими механізмами ООП (інкапсуляція, успадкування, поліморфізм), які є у мові програмування Java. Створити консольний застосунок із застосуванням колекцій та файлового введення-виведення для збереження стану програми між запусками.

 **Варіант завдання:** (Варіант 4) Система обліку студентів та курсів.
 
Необхідно реалізувати систему керування навчальним процесом через консоль.

**Основні вимоги:**  Маніпуляції зі студентами, викладачами та курсами.  Список курсів із пагінацією.  Запис студентів на курси, виставлення оцінок та формування залікової книжки студента.  Наявність мінімум 2-3 факультетів.  Серіалізація для збереження інформації про студентів, курси та успішність у файл.  

**Теоретичні відомості та застосовані принципи ООП**

Під час розробки застосунку були використані такі принципи об'єктно-орієнтованого програмування:

Інкапсуляція: Усі поля даних у класах моделей (наприклад, Student, Course) приховані за допомогою модифікатора private або protected. Доступ до них здійснюється виключно через публічні методи (геттери) або спеціальні методи зміни стану (наприклад, setGrade()).  Успадкування: Створено абстрактний базовий клас Person (Людина), який містить спільні поля id та name. Від нього успадковуються класи Student (Студент) та Teacher (Викладач).  Поліморфізм: У базовому класі Person оголошено абстрактний метод getRole(). Класи-спадкоємці реалізують цей метод по-різному, повертаючи відповідну роль (наприклад, "Студент" або "Викладач (Назва кафедри)").  4. Архітектура програмиДля забезпечення якості та розширюваності коду було застосовано професійний підхід на основі багатошарової архітектури (Layered Architecture), що дозволило розділити відповідальність (відповідно до принципу SRP - Single Responsibility Principle).Структура пакетів:model: Містить класи-сутності предметної області (Student, Teacher, Course, Faculty, Person).repository: Відповідає за збереження та завантаження даних. Використано сучасну бібліотеку Gson від Google та пакет java.nio для серіалізації даних у зручний текстовий формат JSON замість застарілого бінарного I/O.  service: Містить бізнес-логіку програми (UniversityService). Виконує перевірки на існування об'єктів перед виставленням оцінок чи записом на курс.ui: Відповідає за взаємодію з користувачем через консоль (ConsoleUI). Перехоплює помилки та виводить зручне меню з пагінацією.  exception: Містить власні класи винятків (наприклад, EntityNotFoundException) для обробки непередбачених ситуацій.

**Інструкція з тестування (Користувацький сценарій)**

Для перевірки працездатності програми передбачено наступний сценарій:

Запустити програму. За відсутності бази даних система автоматично створить порожню.

Вибрати пункт 2 (Додати студента). Ввести унікальний ID, ім'я та обрати факультет (IT, Економіка та управління або Гуманітарні технології).

Вибрати пункт 3 (Додати курс). Ввести ID курсу, назву дисципліни, ім'я викладача та кафедру.

Вибрати пункт 1 (Список курсів). Перевірити роботу пагінації (сторінкового виводу), яка відображає по 2 предмети на екран.  

Вибрати пункт 4 (Записати студента на курс). Ввести раніше створені ID студента та курсу.  

Вибрати пункт 5 (Виставити оцінку). Ввести ID студента, ID курсу та оцінку в балах. 

Вибрати пункт 6 (Залікова книжка). Ввести ID студента. 

Програма згенерує звіт про предмети та бали, які отримав студент.  

Вибрати пункт 0 (Вийти). Дані будуть збережені у файл university.json. При наступному запуску програми всі студенти та оцінки будуть відновлені.  Крім ручного тестування, бізнес-логіка програми (успадкування, поліморфізм, перевірка оцінок) покрита модульними тестами за допомогою фреймворку JUnit 5.

**Висновок** Під час виконання лабораторної роботи було створено повноцінну консольну систему для керування навчальним процесом. Було на практиці закріплено розуміння ключових парадигм ООП (успадкування, поліморфізму, інкапсуляції), роботу з колекціями (List, Map) для зберігання зв'язків між студентами та курсами. Застосування багатошарової архітектури, власних винятків та JSON-серіалізації дозволило зробити програму надійною, розширюваною та наближеною до стандартів комерційної розробки програмного забезпечення.
